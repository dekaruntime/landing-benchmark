# 2026-08-28 — i9-10910, 20 cores

Two runs on the same machine. The second is the one to cite: all four runtimes
were measured in one session, on a quieter box.

## Run 2 — all four together (preferred)

```
host   : Intel(R) Core(TM) i9-10910 CPU @ 3.60GHz, 20 cores
load   : 7.49 7.41 7.83
node   : v26.3.1   bun: 1.4.0   deno: 2.9.6   deka: 0.34.0
oha    : oha 1.16.0
params : 50 connections, 10s per run, median of 3, 5s warmup discarded
```

| runtime | configuration               |   req/s | runs                        |
|---------|-----------------------------|---------|-----------------------------|
| Node    | one event loop (default)    |  30,857 | 28,905 / 30,857 / 32,136    |
| Deno    | one event loop (default)    |  86,217 | 77,670 / 86,217 / 101,723   |
| Bun     | one event loop (default)    |  86,707 | 86,981 / 81,906 / 86,707    |
| deka    | one loop per core (default) | 139,301 | 139,301 / 141,718 / 124,350 |

**Deno and Bun are tied.** 86,217 against 86,707 is a 0.6% difference, far inside
the run-to-run spread of either. Do not report one as faster than the other on
the strength of this.

**Deno's spread is wide** — 77,670 to 101,723, a 31% range across three runs.
Its median is the least trustworthy figure in the table.

## Run 1 — earlier, busier machine, no Deno

```
load   : 15.87 13.93 10.06
```

| runtime      | configuration               |   req/s | runs                        |
|--------------|-----------------------------|---------|-----------------------------|
| Node         | one event loop (default)    |  36,827 | 36,827 / 38,192 / 36,787    |
| Bun          | one event loop (default)    |  91,343 | 98,838 / 90,472 / 91,343    |
| deka         | one loop per core (default) | 141,579 | 137,092 / 156,023 / 141,579 |
| Node cluster | 20 workers (opt-in)         | 111,790 | 111,314 / 112,325 / 111,790 |

Node and Bun both came out *higher* on the busier machine, which is a good
reminder of how much these numbers move between sessions. deka landed within
1.6% across the two runs (141,579 and 139,301); treat that as the only
consistency claim supported here.

## Caveats

- **deka ran on compiler v1** (`DEKA_COMPILER=v1`). The default compiler cannot
  serve on 0.34.0 — [deka#330](https://github.com/dekaruntime/deka/issues/330).
  The runtime is the same either way and the handler is trivial, so this is a
  runtime measurement, but it is not the default path and should be re-taken
  once v2 serves.
- **Bun `reusePort` was not measured.** Only Node has a tuned figure, so the
  tuned comparison is incomplete.
- **50 connections may not saturate 20 cores.** No concurrency sweep was run, so
  none of these are necessarily each runtime's ceiling.
- The load generator shares the machine with the server throughout.

Indicative, not authoritative. Run it yourself.
